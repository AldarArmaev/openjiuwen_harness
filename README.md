# openJiuwen Hackathon Harness

Однопроходный агент для решения размеченного датасета задач
(`math` / `data_analysis` / `search` / `coding`) в пределах лимита токенов
и одного часа. Харнесс построен поверх **openJiuwen** (`openjiuwen==0.1.19`)
— единственная точка интеграции с фреймворком находится в
[`harness/models.py`](harness/models.py).

## Контракт запуска

Проверяющая сторона запускает контейнер командой из регламента:

```bash
docker build -t "hack:latest" .
docker run --rm \
  -e LLM_BASE_URL -e LLM_API_KEY \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --workdir /app --entrypoint python \
  "hack:latest" /app/run_agent.py --tasks-dir /data/tasks
```

Аргументы / окружение:

| Параметр | Источник | Назначение |
|---|---|---|
| `--tasks-dir` (или `$TASKS`) | аргумент / env | каталог с задачами; в каждой подпапке — `task.json` и `workspace/` |
| `--out` (или `$OUT`) | аргумент / env, по умолчанию `/tmp/out` | куда писать журнал, `state.json` и копии решений |
| `$LLM_BASE_URL`, `$LLM_API_KEY` | env | адрес прокси LLM и ключ (ключ **не** хранится в репозитории) |
| `$AGENT_MODEL` | env, опц. | имя модели (по умолчанию `qwen3.8-27b-noreason`) |
| `$AGENT_TOKEN_LIMIT` | env, опц. | лимит юнитов (по умолчанию `400000`) |

Корневая ФС контейнера смонтирована `--read-only`; единственная запись —
в `--tmpfs /tmp` и в rw-монтирование `/data/tasks`. По умолчанию `--out`
указывает на `/tmp/out`, чтобы состояние агента не падало на read-only корень.

## Как сохраняются решения

Требование регламента: решение сохраняется **после каждой** решённой задачи,
а для каждой задачи в её каталоге создаётся `answer.txt`.

- `Store.save()` ([`harness/store.py`](harness/store.py)) атомарно пишет
  `answer.txt` (запись через временный файл + `os.replace`) в
  `workspace/` задачи **и** в выходной каталог;
- после каждой задачи обновляется `state.json` — множество уже решённых id.
  Прогон, прерванный по таймауту или лимиту токенов, не теряет ни одного
  сохранённого решения и может быть продолжен;
- `answer.txt` пишется обратно в `$TASKS` (rw-монтирование) — именно его
  читает грейдер.

## Структура

```
run_agent.py        точка входа: цикл по задачам, дедлайн, бюджет
Dockerfile          python:3.12-slim + openjiuwen==0.1.19
requirements.txt    фиксированные версии pandas/numpy/sklearn/matplotlib/openpyxl
harness/
  models.py         построение клиента openJiuwen (OpenAI-совместимый прокси)
  planner.py        детерминированный порядок обхода задач
  triage.py         детерминированные эвристики для search-задач
  executor.py       цикл инструментов для одного типа задачи
  strategies.py     промпты-стратегии + песочница выполнения кода
  tools.py          чтение/запись файлов, инвентарь workspace
  budget.py         учёт расхода токенов и резерв на следующую задачу
  store.py          crash-safe сохранение ответов и журнала
```

## Учёт расхода токенов (billing)

Бюджет ведёт [`harness/budget.py`](harness/budget.py); единица — «юнит»:

```
units = ⌊input_tokens / 10⌋ + output_tokens
```

`input_tokens` — это `prompt_tokens` прокси, `output_tokens` — `completion_tokens`
(в openJiuwen `output_tokens = response.usage.completion_tokens`, поэтому
рассуждающие токены уже входят в стоимость выхода и отдельно не начисляются).
Кэш-токены `cached_tokens` **не** вычитаются — это консервативная оценка.
Счётчик берётся из `usage` каждого ответа прокси
(`harness/executor.py`), кэш **не** вычитается. Перед каждой задачей
проверяется резерв `MIN_TASK_RESERVE` плюс пер-задачный бюджет
(`--task-budget`); при нехватке прогон останавливается, сохранив всё
решённое. Лимит по времени — 55 минут с запасом 90 секунд до часовой границы
контейнера.

## Поиск невыполнимых задач

Два механизма, оба не тратят токены зря:

1. **Детерминированный триаж** (`harness/triage.py`) — только для `search`:
   если в `workspace/` нет ни одного текста-носителя (пустой каталог либо
   только бинарники), задача помечается неразрешимой и получает `skip` без
   обращения к модели.
2. **Skip от модели** — каждая стратегия содержит явный контракт: если для
   ответа не хватает данных (отсутствует файл, значение указано как `?`,
   начальное состояние не задано), агент вызывает инструмент `skip` с
   кратким обоснованием вместо угадывания. Такие skip'и пишутся в
   `<out>/tasks/<task_id>.skip` и не считаются решёнными задачами.

Пустой/недостающий `answer.txt` для пропущенной задачи не создаётся, чтобы
грейдер не засчитал догадку как ответ.

## Траектории (journal)

Каждый прогон пишет JSONL-журнал `<out>/agent.log`, по объекту на событие:
`start`, `triage`, `call` (с полями `usage`), `tool`/`action`, `submit`,
`skip`, `run_stop`, `finish`. Каждая запись содержит `at` (секунды с старта)
и `spent` (накопленные юниты) — этого достаточно, чтобы восстановить полную
траекторию любой задачи и проверить расход.

## Сборка и запуск локально

```bash
# сборка (все загрузки — на этапе build; в рантайме сеть не нужна)
docker build -t hack:latest .

# запуск на папке с задачами
mkdir -p /tmp/out
docker run --rm -e LLM_BASE_URL=... -e LLM_API_KEY=... \
  -v "$PWD/task-dir:/data/tasks:rw" --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --workdir /app --entrypoint python hack:latest \
  /app/run_agent.py --tasks-dir /data/tasks
```

## Ограничения

- Репозиторий < 100 МБ без `.git`; собранный образ < 4 ГБ; сборка ≤ 1000s.
- Ключей API в репозитории нет — прокси-ключ передаётся при запуске.
- Версии зависимостей и тег базового образа (`python:3.12-slim-bookworm`)
  зафиксированы; в рантайме ничего не скачивается.
